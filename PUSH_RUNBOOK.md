# OneSignal Web SDK v16

The web SDK loads after an eligible signed-in member selects **Set up this device** in Inbox. **Allow on this device** invokes the browser opt-in action. The site uses its existing Inbox controls and never enables the floating OneSignal button. The root PWA worker remains at `/`. The OneSignal worker is at `/push/onesignal/OneSignalSDKWorker.js` with scope `/push/onesignal/`. The worker route must be public with a JavaScript content type. [Worker documentation](https://documentation.onesignal.com/docs/en/onesignal-service-worker)

## Test rollout

1. Confirm the club audience and privacy arrangements with the organization responsible for the site. OneSignal says it does not knowingly collect personal information from people under 18. Confirm the provider's applicability before enabling delivery, and use designated eligible test accounts only. The Free plan lists 10,000 web push subscribers per send. [Privacy policy](https://onesignal.com/privacy_policy/) · [Pricing](https://onesignal.com/pricing)
2. Use an eligible HTTPS preview with an isolated Neon branch and a OneSignal app configured for that exact origin. Apply the additive schema using the preview database's direct URL. Configure App ID, Safari Web ID and REST API key through protected host environment settings. Generate the ES256 identity key in OneSignal, base64-encode its private PEM locally, and store it as `ONESIGNAL_IDENTITY_PRIVATE_KEY_BASE64`. Set `ONESIGNAL_IDENTITY_VERIFIED=true` only after the matching dashboard toggle is enabled. [Identity Verification](https://documentation.onesignal.com/docs/en/identity-verification)
3. Set `PUSH_TEST_MEMBER_IDS` to the comma-separated internal IDs of designated testers, `PUSH_MODE=test`, and configure `CRON_SECRET` as an independent server secret. After confirming eligibility, set `PUSH_AUDIENCE_APPROVED=true` and `PUSH_ENABLED=true` for that environment only.
4. On desktop, Android and compatible installed iOS PWAs, sign in and opt in from Inbox. Verify a test-only publication reaches the intended device, opens the correct portal section, and still appears in the inbox. Verify opt-out, logout, unrelated committee visibility, test allowlist, permission denial and browser worker scopes. [iOS setup](https://documentation.onesignal.com/docs/en/ios-web-push-setup)
5. The app queues eligible members from the same transaction that creates the existing inbox event. A write processes up to three due deliveries, and the authenticated Vercel cron drains up to twelve per daily invocation. Scheduled quizzes generate an event through cron on their Cairo date. Dispatch retries reuse the same provider idempotency key and recheck current member access and preferences. Delivery summaries are visible to the President. Provider acceptance and actual device delivery are separate checks.

The per-recipient queue is sized for a limited test rollout. Measure and improve batching or drain capacity before enabling a broad audience. A busy queue may outlast the daily cron and messages expire after 24 hours. Keep `PUSH_ENABLED=false` until test delivery and account eligibility are verified. Roll back by disabling push in the environment and redeploying, leaving the Inbox available.
